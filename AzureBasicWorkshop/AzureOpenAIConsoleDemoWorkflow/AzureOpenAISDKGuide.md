# Azure OpenAI: как работало раньше и как работает через SDK

## 1) Как это работало раньше в этом проекте
Ранее практическая часть использовала детерминированную fallback-логику без реальных сетевых вызовов в Azure OpenAI.

Что происходило в каждом демо-методе:
- `RunBasicPromptAsync` возвращал фиксированную строку.
- `RunStructuredOutputAsync` генерировал локальный JSON и парсил его в `SupportTicketAnalysis`.
- `RunBusinessCaseAsync` формировал action items из входных тикетов через локальный LINQ.

Почему этот подход был полезен:
- Демо стабильно работало офлайн.
- Не было зависимости от облачной конфигурации.
- Предсказуемый и стабильный результат для презентации.

Ограничения:
- Нет реального model inference.
- Нет реального потребления токенов, задержек и поведения Azure-сервиса.
- Подход не подходит для демонстрации production-интеграции.

## 2) Как это работает сейчас через Azure OpenAI SDK
Теперь workflow сначала пытается выполнить реальный вызов Azure OpenAI через SDK, а если конфигурация/сеть недоступны — аккуратно переключается на детерминированный fallback.

Текущий поток выполнения:
1. Чтение настроек окружения:
   - `AZURE_OPENAI_ENDPOINT`
   - `AZURE_OPENAI_DEPLOYMENT`
   - `AZURE_OPENAI_KEY` (опционально)
2. Создание `AzureOpenAIClient`.
3. Получение `ChatClient` для нужного deployment.
4. Отправка chat-сообщений (`SystemChatMessage` + `UserChatMessage`).
5. Чтение текста ответа из `completion.Value.Content`.
6. При любой ошибке возврат fallback-результата, чтобы демо не прерывалось.

Варианты аутентификации:
- API Key: используется, если задан `AZURE_OPENAI_KEY`.
- Microsoft Entra / Managed Identity: используется через `DefaultAzureCredential`, если ключ не задан.

## 3) Почему SDK-подход лучше для реальных сценариев
Преимущества:
- Типобезопасный .NET API (меньше ручного HTTP-кода).
- Проще переключаться между способами аутентификации (ключ vs Entra identity).
- Более чистая работа с запросами/ответами для chat completion.
- Лучшая поддерживаемость кода для production.

Компромиссы:
- Нужен Azure-ресурс и деплой модели.
- Нужны управление конфигурацией и безопасное хранение секретов.
- Нужно обрабатывать сетевые/аутентификационные ошибки (в этом демо это закрыто fallback-механизмом).

## 4) Быстрый чеклист запуска
Для реальных SDK-вызовов задайте переменные в PowerShell (пример):
- `$env:AZURE_OPENAI_ENDPOINT = "https://<your-resource>.openai.azure.com/"`
- `$env:AZURE_OPENAI_DEPLOYMENT = "<your-deployment-name>"`
- `$env:AZURE_OPENAI_KEY = "<your-api-key>"` (опционально при использовании Entra auth)

Затем выполните:
- `dotnet run --project AzureOpenAIConsoleDemoWorkflow`

Если настройки не заданы, приложение продолжит работать в fallback-режиме для стабильной демонстрации.

## 5) Коротко (для презентации)
- Раньше: только локальная детерминированная симуляция.
- Сейчас: сначала реальный SDK-вызов, затем безопасный fallback.
- Итог: и реалистичность для production, и надежность для демо.
