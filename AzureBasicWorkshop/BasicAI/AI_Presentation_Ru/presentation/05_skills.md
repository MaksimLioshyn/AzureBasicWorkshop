# 🎯 Skills — Модульные переиспользуемые навыки

---

## 1. Заголовок и краткое определение

**Skill (навык)** — это упакованный, переиспользуемый модуль компетенций, который можно вызвать по имени или автоматически по контексту. В отличие от Instructions (которые задают общее поведение), Skills — это конкретные «способности», которые AI применяет для решения специфических задач.

---

## 2. Подробное объяснение

### Простыми словами
Если Instructions — это «как ты ведёшь себя в целом», то Skills — это «что конкретно ты умеешь делать». Навык анализа кода, навык составления резюме, навык разбора ошибок — каждый это отдельный модуль с чёткими инструкциями о том, как выполнять задачу.

В GitHub Copilot, например, Skills — это отдельные Markdown-файлы (`SKILL.md`) с детальными инструкциями по выполнению специализированной задачи.

### Технически
Skills хранятся как:
- **Текстовые файлы** (Markdown) с инструкциями
- **Вызываются** агентом или системой при совпадении контекста
- **Состоят из**: описания, триггеров, шагов выполнения, примеров, ожидаемого результата
- Реализуют принцип **Single Responsibility** — один навык = одна задача

```
┌─────────────────────────────────────────────────────────┐
│                      AGENT / SYSTEM                      │
│                                                          │
│  "Проанализируй код"                                     │
│          │                                               │
│          ▼ (агент определяет нужный навык)               │
│  ┌───────────────────────────────────────────────────┐   │
│  │  SKILL: code-analysis                             │   │
│  │  ─────────────────                               │   │
│  │  Триггеры: "проанализируй код", "найди баги"     │   │
│  │  Шаги:                                           │   │
│  │    1. Прочитай код                               │   │
│  │    2. Проверь синтаксис                          │   │
│  │    3. Найди уязвимости                           │   │
│  │    4. Оцени производительность                  │   │
│  │    5. Предложи рефакторинг                      │   │
│  │  Формат вывода: structured report               │   │
│  └───────────────────────────────────────────────────┘   │
│          │                                               │
│          ▼ (навык применён к контексту)                  │
│      Структурированный анализ кода                       │
└─────────────────────────────────────────────────────────┘
```

## 3. Аналогия из реальной жизни

**Skill = Профессиональные компетенции сотрудника**

Мария — IT-консультант с несколькими компетенциями:
- ✅ Навык: «Диагностика сети» — знает алгоритм, инструменты, типичные проблемы
- ✅ Навык: «Настройка VPN» — чёткая процедура из 12 шагов
- ✅ Навык: «Составление технического отчёта» — структура, стандарт, примеры

Когда к ней приходит задача «настрой VPN», она **автоматически активирует** нужную компетенцию — не изобретает процедуру каждый раз заново, а применяет отработанный алгоритм.

**Ключевые свойства навыка:**
- Описан → можно передать другому человеку (переиспользование)
- Специализирован → чётко для одной задачи
- Активируется по контексту → не нужно явно напоминать

## 4. Как это работает — Механика

### Жизненный цикл Skill:

```
1. СОЗДАНИЕ
   Разработчик/эксперт описывает навык в SKILL.md
   
2. РЕГИСТРАЦИЯ
   Навык добавляется в библиотеку навыков системы
   
3. ОБНАРУЖЕНИЕ
   Агент или система анализирует задачу пользователя
   и находит подходящий навык
   
4. ВЫЗОВ
   Навык загружается в контекст → AI следует инструкциям навыка
   
5. ВЫПОЛНЕНИЕ
   AI применяет шаги навыка к конкретной задаче
   
6. РЕЗУЛЬТАТ
   Навык возвращает структурированный вывод
```

### Структура файла SKILL.md (GitHub Copilot):

```markdown
---
name: code-review
description: Проводит детальный код-ревью с рекомендациями
triggers: ["review", "проверь код", "code review", "код-ревью"]
---

# Навык: Код-ревью

## Когда применять
Когда пользователь просит проверить, проанализировать или 
сделать ревью кода.

## Шаги выполнения

1. **Читай код** целиком перед комментариями
2. **Проверь структуру**: архитектура, разделение ответственности
3. **Найди баги**: логические ошибки, edge cases
4. **Оцени безопасность**: OWASP Top 10, injection, auth
5. **Проверь производительность**: N+1, лишние запросы, memory leaks
6. **Стиль**: соответствие code style, naming conventions
7. **Тесты**: покрытие, качество тестов

## Формат вывода
Структурированный отчёт с секциями: Critical / Major / Minor / Suggestions
```

## 5. Примеры кода и использования

### Пример 1: Простой навык анализа ошибок (Python)
```python
# skill_error_analysis.py — библиотека навыка

SKILL_ERROR_ANALYSIS = """
# Навык: Анализ ошибок

## Инструкции
При анализе ошибки или исключения:

1. Определи тип ошибки (SyntaxError, RuntimeError, etc.)
2. Локализуй место в коде (файл, строка, функция)
3. Объясни причину простыми словами (1-2 предложения)
4. Покажи исправленный код
5. Дай совет по предотвращению в будущем

## Формат ответа
### Тип ошибки: [название]
### Место: [файл:строка]
### Причина: [объяснение]
### Исправление:
```python
[исправленный код]
```
### Совет: [рекомендация]
"""

def analyze_error(error_message: str, code_context: str) -> str:
    """Применяет навык анализа ошибок к конкретной ошибке."""
    prompt = f"""
    {SKILL_ERROR_ANALYSIS}
    
    ---
    Ошибка:
    {error_message}
    
    Контекст кода:
    {code_context}
    """
    return call_llm(prompt)
```

### Пример 2: Навык форматирования документации
```markdown
# SKILL.md — Документирование API

## Описание
Генерирует документацию для REST API endpoints

## Триггеры
- "задокументируй endpoint"
- "напиши документацию для API"
- "добавь swagger docstring"

## Шаги
1. Определи HTTP метод и путь
2. Опиши назначение endpoint'а (1 предложение)
3. Задокументируй параметры запроса (query, body, path)
4. Опиши возможные ответы (200, 400, 401, 404, 500)
5. Добавь пример запроса и ответа (curl + JSON)

## Стандарт
Используй OpenAPI 3.0 / Swagger формат

## Пример вывода
```
POST /api/v1/users
Создаёт нового пользователя в системе

Parameters:
  Body (required):
    - name: string (2-100 chars)
    - email: string (valid email)
    
Responses:
  201: Created - возвращает созданного пользователя
  400: Bad Request - невалидные данные
  409: Conflict - email уже существует
```
```

### Пример 3: Вызов Skills в LangChain-стиле
```python
from langchain.tools import Tool
from langchain.agents import AgentExecutor

# Определяем набор навыков как Tools
skills = [
    Tool(
        name="CodeAnalysis",
        description="Анализирует код на баги, безопасность и производительность",
        func=lambda code: analyze_code(code)
    ),
    Tool(
        name="TestGeneration", 
        description="Генерирует unit-тесты для переданного кода",
        func=lambda code: generate_tests(code)
    ),
    Tool(
        name="Refactoring",
        description="Предлагает рефакторинг кода с объяснением",
        func=lambda code: suggest_refactoring(code)
    ),
    Tool(
        name="Documentation",
        description="Генерирует документацию (docstrings, README)",
        func=lambda code: generate_docs(code)
    )
]

# Агент сам выбирает нужный навык
agent = AgentExecutor(agent=llm_agent, tools=skills)

result = agent.run("Проанализируй этот код и напиши тесты: \n" + my_code)
# Агент автоматически применит CodeAnalysis + TestGeneration
```

### Пример 4: Навык-пайплайн (составной навык)
```yaml
# skill-cv-review.yaml
name: cv-review
description: Полный анализ резюме кандидата для HR

steps:
  - name: parse
    skill: document-extraction
    action: "Извлеки структурированные данные из резюме"
    
  - name: evaluate  
    skill: hr-assessment
    action: "Оцени соответствие требованиям вакансии"
    requires: [parse.output]
    
  - name: score
    skill: scoring
    action: "Выставь оценку по критериям (0-10)"
    requires: [evaluate.output]
    
  - name: report
    skill: report-generation  
    action: "Сформируй итоговый отчёт для рекрутера"
    requires: [parse.output, evaluate.output, score.output]
```

## 6. Плюсы

1. **Переиспользование** — написал навык один раз, используешь во всех проектах. Обновил один файл — обновилось поведение везде.

2. **Модульность** — каждый навык — отдельная единица с чёткими входом/выходом. Легко тестировать, заменять, улучшать.

3. **Специализация** — навык содержит экспертизу конкретной области. Навык «анализ безопасности» знает OWASP Top 10. Навык «HR-оценка» знает критерии найма.

4. **Командная работа** — разные специалисты пишут разные навыки (HR пишет hr-навыки, DevOps пишет devops-навыки), а потом используют чужие.

5. **Версионирование и аудит** — Skills в git → можно отследить, кто изменил навык, когда и почему.

6. **Стандартизация** — все используют одинаковый формат отчёта, одинаковую процедуру проверки.

---

## 7. Минусы / Ограничения

1. **Накладные расходы на создание** — нужно потратить время на описание навыка, тестирование, документирование. Для одноразовых задач не стоит.

2. **Обновляемость** — если изменился стандарт (новая версия фреймворка, новые требования), нужно обновлять навык. Устаревшие навыки дают неверные результаты.

3. **Конфликты навыков** — если навыки пересекаются по тематике, агент может выбрать неправильный. Нужна чёткая документация границ каждого навыка.

4. **Не заменяют данные** — Skills знают «как делать», но не знают «с чем делать» прямо сейчас. Для доступа к актуальным данным нужны MCPs.

## 8. Когда использовать / Когда НЕ использовать

### ✅ Используй Skills когда:
- Задача повторяется регулярно (код-ревью каждый PR, анализ резюме каждого кандидата)
- Нужна специализированная экспертиза для конкретной задачи
- Работаешь в команде — хочешь стандартизировать подходы
- Строишь AI-агента, которому нужны разные «способности»
- Хочешь переиспользовать логику между проектами

### ❌ НЕ используй Skills когда:
- Задача уникальна и не повторится (напиши промпт разово)
- Нужен доступ к внешним данным (это MCPs)
- Skills выполняют ровно одну функцию — не пытайся сделать «мегонавык» на всё

## 9. Сравнение с соседними концептами

### Skills vs Instructions

| Критерий | Skills | Instructions |
|----------|--------|-------------|
| Назначение | Конкретная способность | Общее поведение |
| Количество | Много разных | Один набор правил |
| Активация | По задаче/контексту | Всегда |
| Специфичность | Высокая | Общая |
| Пример | «Сделай ревью кода» | «Будь вежлив, пиши на RU» |

### Skills vs MCPs

| Критерий | Skills | MCPs |
|----------|--------|------|
| Что дают | Способность делать | Доступ к данным/инструментам |
| Содержат | Инструкции и алгоритмы | Подключения к внешним системам |
| Пример | «Как анализировать резюме» | «Читать файл резюме из диска» |
| Аналогия | Профессиональный навык | Рабочий инструмент |

## 10. Заметки для спикера

- **Конкретный пример из Copilot** — покажи реальный файл SKILL.md из своего воркспейса. Аудитория поймёт, что это не абстракция
- **Аналогия с компетенциями HR** — почти все в аудитории проходили собеседования и знают «профиль компетенций». Это работает отлично
- **Отличие от Instructions** — повтори: Instructions = правила поведения, Skills = конкретные умения. Это как личность vs профессия
- Подчеркни **командный аспект** — разные люди пишут разные skills, потом используют чужие. Это коллаборация
- Время на этот слайд: **5–6 минут**

## 11. Возможные вопросы аудитории

**В: Чем Skills отличаются от обычных функций в коде?**
> О: Skills — это инструкции для AI, написанные на естественном языке. Функции в коде — детерминированный алгоритм на языке программирования. Skills гибкие (AI интерпретирует контекст), функции точные (выполняют строго то, что написано). Skills используются там, где нужна «разумность», функции — там, где нужна точность.

**В: Кто должен создавать Skills в команде?**
> О: Domain experts. HR пишет HR-навыки, DevOps — devops-навыки, QA — навыки тестирования. AI-инженер помогает структурировать и интегрировать. Ключевое правило: навык создаёт тот, кто лучше всех знает эту задачу.

**В: Можно ли вызвать несколько Skills одновременно?**
> О: Да, агент может применять цепочку навыков. Например: parse_document → evaluate_content → generate_report. Это называется «Skill Pipeline» или «Skill Chaining». Именно так работают сложные AI-системы.

**В: Как убедиться, что навык работает правильно?**
> О: Через eval framework: (1) подготовить набор тестовых входных данных с ожидаемыми результатами, (2) прогнать через Azure AI Foundry Eval или LangSmith, (3) оценить качество по метрикам (accuracy, relevance, coherence). Тестирование навыков — обязательная практика.
