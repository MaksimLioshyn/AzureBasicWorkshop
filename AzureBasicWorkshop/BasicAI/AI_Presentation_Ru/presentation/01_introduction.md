# 🚀 Введение: От разового запроса к автономному агенту

---

## 📖 Краткое содержание

В этом разделе мы устанавливаем контекст: почему возникло разнообразие подходов к работе с AI, в чём их принципиальное различие и что аудитория получит от этой презентации.

---

## 🕰️ История: Как развивалось взаимодействие с AI

### Эпоха 1: Командные интерфейсы (до 2020)
В начале AI-системы были узкоспециализированными: распознавание изображений, перевод текста, предсказание цен. С ними взаимодействовали через **API-вызовы**, задавая жёстко структурированные входные данные.

```python
# Типичное взаимодействие эпохи 1
result = model.predict(input_data=[0.5, 0.3, 0.8])
```

Никакого «диалога» — только структурированный вход/выход.

### Эпоха 2: Появление языковых моделей (2020–2022)
GPT-3 (2020) и его преемники открыли новую эпоху: с AI можно было разговаривать на **естественном языке**. Первая реакция: «Напишу запрос — получу ответ». Это и есть **Prompts** — первый уровень нашей иерархии.

```
Пользователь: "Напиши функцию на Python для сортировки списка"
AI: "Конечно! Вот пример: ..."
```

Просто. Мощно. Но ограниченно.

### Эпоха 3: Специализация и настройка (2022–2023)
Компании начали понимать: AI нужно **обучать вести себя определённым образом**. Появились системные промпты (system prompts), fine-tuning, RLHF. Так выросла концепция **Instructions** — задание постоянных правил поведения.

```
System: "Ты — помощник технической поддержки компании X. 
         Отвечай кратко, вежливо, на русском языке.
         Если не знаешь ответа — перенаправляй к специалисту."
```

### Эпоха 4: Инструменты и интеграции (2023–2024)
ChatGPT получил плагины. Copilot начал читать файлы. AI научился **использовать внешние инструменты** — поиск, базы данных, API. Это привело к концепциям **Skills** и **MCPs** (Model Context Protocol).

```json
{
  "tools": [
    {"name": "web_search", "description": "Search the internet"},
    {"name": "read_file", "description": "Read file contents"},
    {"name": "run_code", "description": "Execute Python code"}
  ]
}
```

### Эпоха 5: Автономные системы (2024–сейчас)
Современные AI-системы могут **самостоятельно планировать** и выполнять многошаговые задачи. Появились **Agents** — системы, которые сами решают, какие действия предпринять. И **Workflows** — детерминированные пайплайны для надёжного выполнения бизнес-процессов.

```
🎯 Задача: "Проанализируй наши продажи за квартал и предложи стратегию"

Агент:
  1. Читает данные из БД
  2. Строит статистику
  3. Ищет внешние тренды рынка  
  4. Формирует отчёт
  5. Отправляет на почту
  
→ Всё это без участия человека
```

## ❗ Проблема: Почему одного промпта недостаточно

### Ситуация 1: Непоследовательность
Каждый раз пишешь новый промпт → нет гарантии одинакового стиля и поведения.

```
Запрос 1: "Переведи на английский" → Ответ с пояснениями
Запрос 2: "Переведи на английский" → Только перевод без пояснений
```

**Решение**: Instructions — постоянные правила.

### Ситуация 2: Нет доступа к актуальным данным
Промпт не может достучаться до вашей базы данных, файлов, CRM.

```
Пользователь: "Покажи статистику продаж за сегодня"
AI: "Извините, у меня нет доступа к вашим данным..."
```

**Решение**: MCPs — инструменты для доступа к реальным данным.

### Ситуация 3: Сложные многошаговые задачи
Одним промптом нельзя решить задачу, требующую 10 шагов.

```
Задача: "Найди 5 новых клиентов, напиши им письма, проанализируй ответы"
→ Это не один запрос, это целый процесс
```

**Решение**: Agents или Workflows.

### Ситуация 4: Переиспользование логики
Каждый раз заново пишешь один и тот же сложный промпт.

```
"Проанализируй код на: баги, безопасность, производительность, 
 стиль, тесты, документацию..." → 200 слов каждый раз
```

**Решение**: Skills — упакованная логика готова к вызову.

## 📐 Спектр подходов: Ось «Простота ↔ Автономность»

```
ПРОСТОТА                                           МОЩНОСТЬ
   │                                                   │
   ▼                                                   ▼
Prompts → Instructions → Skills → MCPs → Agents → Workflows

[Быстро]   [Настройка]  [Модуль]  [Данные] [Авто]   [Надёжно]
[Разово]   [Постоянно]  [Повтор]  [Мир]   [Умно]    [Детермин]
```

### Характеристики каждой точки спектра:

| Точка | Кто управляет | Что делает AI | Где граница |
|-------|---------------|---------------|-------------|
| **Prompts** | Человек полностью | Отвечает на запрос | Один ответ |
| **Instructions** | Человек задаёт контекст | Ведёт себя по правилам | Сессия |
| **Skills** | Человек вызывает | Выполняет навык | Один навык |
| **MCPs** | Человек/система | Обращается к инструментам | Один запрос |
| **Agents** | AI решает сам | Планирует и действует | Цель достигнута |
| **Workflows** | Система (по скрипту) | Выполняет этапы | Конец пайплайна |

---

## 💡 Ключевой тезис: Это не конкуренты, а уровни одной системы

**Неправильное мышление** ❌:
> «Агенты лучше промптов, потому что они мощнее»

**Правильное мышление** ✅:
> «Каждый инструмент решает свою задачу. Молоток не лучше отвёртки — просто для разных гвоздей»

### Реальный пример комбинирования:
```
GitHub Copilot — это:
  ✓ Instructions (правила поведения в VS Code)
  ✓ Skills (навыки: анализ кода, автодополнение)
  ✓ MCPs (доступ к файловой системе, терминалу)
  ✓ Agents (агент может запускать тесты, делать коммиты)
  ✓ Workflows (CI/CD интеграция)
  
→ Используют ВСЕ уровни одновременно
```

## 🎓 Что аудитория узнает к концу презентации

По завершении презентации участники смогут:

1. **Чётко объяснить** разницу между Prompt, Instruction, Skill, MCP, Agent и Workflow
2. **Выбрать правильный подход** для любой задачи с AI
3. **Комбинировать** разные уровни для создания мощных систем
4. **Избегать антипаттернов** — когда сложный инструмент применяется там, где достаточно простого
5. **Понимать архитектуру** современных AI-продуктов (Copilot, ChatGPT, Claude и др.)

## 🔑 Ключевые термины этого раздела

| Термин | Определение |
|--------|-------------|
| **LLM** | Large Language Model — большая языковая модель (GPT, Claude, Gemini) |
| **Inference** | Процесс получения ответа от модели |
| **Context Window** | Размер «памяти» модели — сколько текста она видит одновременно |
| **Fine-tuning** | Донастройка модели на специализированных данных |
| **System Prompt** | Скрытые инструкции, задающие поведение AI до начала диалога |
| **Tool Calling** | Способность AI вызывать внешние функции/инструменты |
| **Autonomy** | Степень самостоятельности AI в принятии решений |

## ❓ Возможные вопросы аудитории

**В: Если агенты такие мощные, зачем вообще использовать промпты?**
> О: Потому что это как спрашивать «зачем ходить пешком, если есть машины». Промпт запускается за секунды без настройки. Агент требует архитектуры, тестирования, мониторинга. Для простого вопроса агент — оверкилл.

**В: Не устареют ли промпты с развитием агентов?**
> О: Нет. Агенты внутри используют промпты. Это как спрашивать: «Не устареют ли транзисторы с появлением процессоров?» — процессоры состоят из транзисторов.

**В: Когда лучше начинать с агентов, а не с промптов?**
> О: Когда задача требует более 3–5 последовательных шагов, обращения к нескольким источникам данных или принятия решений по промежуточным результатам. Начни с простого и добавляй сложность по необходимости.

**В: Есть ли примеры, где все 6 уровней используются вместе?**
> О: GitHub Copilot — отличный пример. Он использует Instructions (правила помощника), Skills (навыки работы с кодом), MCPs (доступ к файлам), Agents (выполнение задач), Workflows (CI/CD интеграция).
