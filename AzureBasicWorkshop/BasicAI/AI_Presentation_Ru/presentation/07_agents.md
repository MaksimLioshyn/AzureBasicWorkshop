# 🤖 Agents — Автономные AI-системы

---

## 1. Заголовок и краткое определение

**Agent (агент)** — это автономная AI-система, которая самостоятельно планирует последовательность действий и выполняет их для достижения заданной цели, используя набор доступных инструментов. В отличие от простого ответа на запрос, агент работает в цикле: воспринимает → планирует → действует → анализирует результат → повторяет.

---

## 2. Подробное объяснение

### Простыми словами
Если промпт — это «дай мне ответ», то агент — это «реши задачу». Разница как между ответом на вопрос и поручением выполнить работу. Агент не просто отвечает — он планирует, выбирает инструменты, выполняет действия, анализирует результат и корректирует план.

Ключевое свойство агента: **он сам решает, что делать дальше**, основываясь на промежуточных результатах.

### Технически
Архитектура агента состоит из:
- **LLM Core** (мозг) — принимает решения, планирует действия
- **Tool Use** (руки) — вызывает внешние инструменты (MCPs, APIs, функции)
- **Memory** (память) — хранит контекст, историю, промежуточные результаты
- **Observation** (глаза) — получает обратную связь от инструментов

```
┌───────────────────────────────────────────────────────────┐
│                    AGENT ARCHITECTURE                      │
│                                                           │
│  ┌─────────────────────────────────────────────────────┐  │
│  │              LLM REASONING CORE                     │  │
│  │         (Claude / GPT-4o / Gemini)                  │  │
│  │                                                     │  │
│  │  Goal ──► Plan ──► Select Tool ──► Execute ──► ...  │  │
│  └──────────────────────┬──────────────────────────────┘  │
│                         │                                 │
│      ┌──────────────────┼──────────────────┐             │
│      ▼                  ▼                  ▼             │
│  ┌────────┐       ┌──────────┐      ┌──────────┐         │
│  │  MCP   │       │  Memory  │      │  Other   │         │
│  │ Tools  │       │(short +  │      │ Agents   │         │
│  │        │       │  long)   │      │          │         │
│  └────────┘       └──────────┘      └──────────┘         │
│       │                                                   │
│  [Files][API][DB]                                         │
└───────────────────────────────────────────────────────────┘
```

### Цикл работы агента (ReAct цикл):
```
Thought (Размышление)  →  Что нужно сделать?
Action (Действие)      →  Вызов инструмента
Observation (Наблюдение) → Получение результата
[Повтор до достижения цели]
Final Answer           →  Итоговый ответ пользователю
```

## 3. Аналогия из реальной жизни

**Agent = Самостоятельный сотрудник с правом принятия решений**

Два сценария найма:

**Сценарий A (без агента — промпт-модель):**
Ты: «Нужна информация о конкурентах.»
Помощник: «Конкуренты — это компании, работающие в той же нише...»
Ты: «Нет, мне нужен анализ конкретно наших конкурентов.»
→ Каждый шаг требует твоего участия.

**Сценарий B (с агентом):**
Ты: «Подготовь анализ конкурентов за неделю.»
Агент (сам, без твоего участия):
1. Определяет список конкурентов
2. Ищет их сайты и соцсети
3. Анализирует ценообразование
4. Изучает отзывы клиентов
5. Сравнивает с вашими метриками
6. Составляет отчёт

→ Через час: «Готов отчёт. Основные находки: ...»

**Ключевые характеристики агента:**
- Получает цель → сам разбивает на шаги
- Сам выбирает инструменты
- Адаптирует план по результатам
- Спрашивает человека только при блокере

## 4. Как это работает — Механика

### Детальный цикл ReAct:

```
Запрос: "Найди баги в проекте и создай задачи в Jira"

──────────────────────────────────────────────────────
ИТЕРАЦИЯ 1:
  Thought: "Сначала нужно прочитать код проекта"
  Action: read_directory(path="./src")
  Observation: ["user.py", "auth.py", "payment.py", ...]

──────────────────────────────────────────────────────
ИТЕРАЦИЯ 2:
  Thought: "Проанализирую каждый файл на баги"
  Action: read_file(path="./src/payment.py")
  Observation: [код файла payment.py]

──────────────────────────────────────────────────────
ИТЕРАЦИЯ 3:
  Thought: "Нашёл SQL injection в строке 47. 
           Запишу и проверю следующий файл."
  Action: read_file(path="./src/auth.py")
  Observation: [код файла auth.py]

──────────────────────────────────────────────────────
ИТЕРАЦИЯ N:
  Thought: "Все файлы проверены. Нашёл 3 проблемы.
           Создам задачи в Jira."
  Action: create_jira_issue(
    title="SQL Injection в payment.py:47",
    priority="Critical",
    description="..."
  )
  Observation: {"issue_id": "PROJ-1234", "status": "created"}

──────────────────────────────────────────────────────
FINAL:
  "Нашёл и задокументировал 3 проблемы безопасности:
   - PROJ-1234: SQL Injection (Critical)
   - PROJ-1235: Незащищённый endpoint (High)
   - PROJ-1236: Устаревшая зависимость (Medium)"
```

### Типы агентов:

| Тип | Описание | Пример |
|-----|----------|--------|
| **ReAct Agent** | Думает и действует поочерёдно | LangChain ReAct |
| **Planning Agent** | Сначала создаёт план, потом выполняет | AutoGPT |
| **Multi-Agent** | Несколько агентов работают вместе | AutoGen, CrewAI |
| **Human-in-loop** | Спрашивает подтверждения у человека | Copilot Agent |
| **Reflection Agent** | Оценивает своё собственное качество | Reflexion |

## 5. Примеры кода и использования

### Пример 1: Простой агент с LangChain
```python
from langchain.agents import AgentExecutor, create_react_agent
from langchain_anthropic import ChatAnthropic
from langchain.tools import tool

# Определяем инструменты агента
@tool
def search_web(query: str) -> str:
    """Ищет информацию в интернете"""
    return web_search_api.search(query)

@tool
def read_file(path: str) -> str:
    """Читает содержимое файла"""
    with open(path, 'r') as f:
        return f.read()

@tool
def write_file(path: str, content: str) -> str:
    """Записывает содержимое в файл"""
    with open(path, 'w') as f:
        f.write(content)
    return f"Файл {path} успешно сохранён"

# Создаём агента
llm = ChatAnthropic(model="claude-opus-4-5")
tools = [search_web, read_file, write_file]

agent = create_react_agent(llm=llm, tools=tools, prompt=agent_prompt)
agent_executor = AgentExecutor(
    agent=agent, 
    tools=tools,
    verbose=True,      # Показывает цикл размышлений
    max_iterations=10  # Защита от бесконечных циклов
)

# Запускаем агента
result = agent_executor.invoke({
    "input": "Найди последние новости об Azure AI Foundry "
             "и сохрани краткое резюме в файл summary.md"
})
print(result["output"])
```

### Пример 2: Multi-Agent система с AutoGen
```python
import autogen

# Определяем конфигурацию LLM
config_list = [{"model": "gpt-4o", "api_key": os.getenv("OPENAI_API_KEY")}]

# Агент-планировщик (разбивает задачи)
planner = autogen.AssistantAgent(
    name="Planner",
    system_message="""Ты — планировщик. 
    Получаешь высокоуровневую задачу и разбиваешь её на конкретные шаги.
    Делегируй шаги специализированным агентам.""",
    llm_config={"config_list": config_list}
)

# Агент-разработчик (пишет код)
developer = autogen.AssistantAgent(
    name="Developer",
    system_message="Ты — Python разработчик. Пишешь качественный код с тестами.",
    llm_config={"config_list": config_list}
)

# Агент-ревьюер (проверяет код)
reviewer = autogen.AssistantAgent(
    name="Reviewer", 
    system_message="Ты — код-ревьюер. Проверяешь код на баги и качество.",
    llm_config={"config_list": config_list}
)

# Человек-надзиратель (подтверждает критичные решения)
human = autogen.UserProxyAgent(
    name="HumanSupervisor",
    human_input_mode="TERMINATE",  # Просит ввод только при завершении
    code_execution_config={"work_dir": "coding"}
)

# Запускаем мульти-агентный чат
human.initiate_chat(
    planner,
    message="Создай REST API для управления задачами (CRUD) на FastAPI"
)
```

### Пример 4: Агент для анализа данных (Azure AI Foundry)
```python
# Azure AI Foundry Agent
from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import (
    CodeInterpreterTool,
    FileSearchTool,
    BingGroundingTool
)

# Создаём агента с инструментами
agent = project_client.agents.create_agent(
    model="gpt-4o",
    name="data-analysis-agent",
    instructions="""Ты — аналитик данных.
    Анализируй данные, строй визуализации, делай выводы.
    Всегда объясняй методологию.""",
    tools=[
        CodeInterpreterTool(),   # Запуск Python кода
        FileSearchTool(),        # Поиск по документам
        BingGroundingTool()      # Актуальные данные из интернета
    ]
)

# Запускаем задачу
thread = project_client.agents.create_thread()
project_client.agents.create_message(
    thread_id=thread.id,
    role="user",
    content="Проанализируй продажи за Q4 2024, "
            "найди тренды и создай визуализацию"
)

run = project_client.agents.create_and_process_run(
    thread_id=thread.id,
    agent_id=agent.id
)
```

## 6. Плюсы

1. **Автономность** — агент выполняет сложные многошаговые задачи без постоянного участия человека. Это экономит время для задач типа «исследуй и сообщи».

2. **Адаптивность** — если промежуточный результат не тот, агент корректирует план. Не нужно переформулировать задачу — агент сам справляется с неожиданными ситуациями.

3. **Сила инструментов** — агент комбинирует все нижние уровни: используует MCPs для данных, Skills для обработки, Instructions для поведения.

4. **Масштабируемость задач** — можно поручить агенту задачи, которые заняли бы у человека часы. Агент справится за минуты.

5. **Параллельность** — в мульти-агентных системах разные агенты работают параллельно, многократно ускоряя выполнение.

## 7. Минусы / Ограничения

1. **Галлюцинации и ошибки** — агент может принять неверное решение на основе неверной «логики». Ошибка на шаге 2 ведёт к неверным результатам на шагах 3–10. Без мониторинга это незаметно.

2. **Петли (infinite loops)** — агент может зациклиться: пытается решить задачу → получает ошибку → пытается снова → ... Нужны лимиты итераций.

3. **Высокая стоимость** — каждый вызов LLM платный. Агент делает десятки вызовов на одну задачу. Без контроля затраты быстро растут.

4. **Сложность отладки** — «Почему агент сделал X вместо Y?» — ответить сложно. Нужен детальный logging каждого шага (трассировка).

5. **Риски безопасности** — агент с правом записи в файловую систему или отправки emails может нанести реальный ущерб при неверном решении или атаке.

6. **Непредсказуемость** — в отличие от Workflow, поведение агента в нестандартных ситуациях сложно предсказать заранее.

## 8. Когда использовать / Когда НЕ использовать

### ✅ Используй Agents когда:
- Задача многошаговая и требует принятия промежуточных решений
- Нужен исследовательский подход (агент сам ищет нужную информацию)
- Задача нетривиальная и нельзя предсказать все шаги заранее
- Нужна адаптация к промежуточным результатам
- Высокая ценность задачи оправдывает стоимость многих LLM-вызовов

### ❌ НЕ используй Agents когда:
- Задача простая и решается одним промптом
- Нужна 100% предсказуемость и надёжность (используй Workflow)
- Бюджет ограничен — агенты дорогие
- Задача требует точного, детерминированного алгоритма
- Контекст очень чувствителен к ошибкам (финансовые операции, медицина)

## 9. Сравнение с соседними концептами

### Agents vs MCPs

| Критерий | Agents | MCPs |
|----------|--------|------|
| Роль | Принимает решения | Предоставляет инструменты |
| Автономность | Высокая | Нет |
| Цикл | Итеративный | Один вызов |
| Пример | «Реши задачу» | «Прочитай файл» |

### Agents vs Workflows

| Критерий | Agents | Workflows |
|----------|--------|-----------|
| Управление потоком | AI решает динамически | Код определяет статично |
| Предсказуемость | Низкая | Высокая |
| Гибкость | Высокая | Низкая |
| Надёжность | Средняя | Высокая |
| Отладка | Сложная | Простая |
| Стоимость LLM | Высокая | Умеренная |
| Когда лучше | Нестандартные задачи | Бизнес-процессы |

**Золотое правило:**
> Агент — когда нельзя заранее написать алгоритм.  
> Workflow — когда можно и нужно.

## 10. Заметки для спикера

- **Аналогия «самостоятельный сотрудник»** — очень сильная. Все понимают разницу между «ответь на вопрос» и «выполни задачу»
- **Демо ReAct цикла** — если есть Copilot Agent Mode, покажи живую демонстрацию многошагового действия
- **Риски** — для корпоративной аудитории это важно. Агент с правом записи = сотрудник с доступом. Нужна авторизация
- **Agents vs Workflows** — ключевое противоречие. Подчеркни: агент = гибкость, workflow = надёжность. В бизнесе часто нужна надёжность
- **Стоимость** — если аудитория технически подготовлена, можно упомянуть: один агентский run = 10-50 LLM вызовов = $0.5–5
- Время на этот слайд: **8–10 минут** (самый сложный концепт)

## 11. Возможные вопросы аудитории

**В: Чем агент отличается от обычного скрипта с вызовами AI?**
> О: Скрипт выполняет заранее написанный алгоритм. Агент **сам принимает решения** о следующем шаге на основе промежуточных результатов. Скрипт: `if error: do_X` — заранее написано. Агент: «получил ошибку — придумаю, как обойти» — решает динамически.

**В: Насколько безопасно давать агенту право выполнять действия?**
> О: Требует осторожности. Best practices: (1) принцип минимальных привилегий — давай только нужные права, (2) sandbox окружение для деструктивных операций, (3) human-in-the-loop для критичных действий, (4) полное логирование каждого действия, (5) лимит операций и стоимости.

**В: Что такое «агентские петли» и как с ними бороться?**
> О: Когда агент зацикливается: пробует действие → получает ошибку → пробует снова → ... Защиты: (1) `max_iterations=10` — лимит шагов, (2) детектор повторяющихся действий, (3) таймаут на весь run, (4) бюджет на стоимость LLM-вызовов.

**В: Может ли агент работать без интернета, только локально?**
> О: Да! Есть полностью локальные агенты: Ollama + локальная модель + локальные MCP-серверы. Подходит для чувствительных данных. Ограничение — локальные модели слабее GPT-4o/Claude по качеству рассуждений.

**В: Как отладить агента, если он принял неверное решение?**
> О: Ключ — трассировка каждого шага. Инструменты: LangSmith (для LangChain), Azure AI Foundry Traces, Arize. Включай `verbose=True`, логируй каждый Thought/Action/Observation. Анализируй где агент «свернул не туда».
