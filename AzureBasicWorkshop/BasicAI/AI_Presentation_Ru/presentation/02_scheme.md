## 📋 Краткие определения концептов

### 💬 Prompt (Промпт)
**Разовый текстовый запрос к языковой модели.**  
Самый базовый уровень взаимодействия. Вы пишете — AI отвечает. Каждый запрос независим, контекст не сохраняется между разными сессиями. Основа всего.

### 📋 Instructions (Инструкции)
**Постоянные правила поведения AI, заданные заранее.**  
Это system prompt или файл с инструкциями (например, `.github/copilot-instructions.md`), который определяет роль, стиль, ограничения и контекст работы AI. Действуют на протяжении всей сессии или проекта.

### 🎯 Skills (Навыки)
**Переиспользуемые модульные блоки компетенций.**  
Упакованные знания и инструкции для выполнения специфической задачи. Skills вызываются по имени или автоматически при совпадении контекста. Примеры: навык анализа кода, навык написания тестов.

### 🔌 MCP (Model Context Protocol)
**Стандартный протокол подключения внешних инструментов и данных к AI.**  
Открытый стандарт от Anthropic (2024), позволяющий AI обращаться к файлам, базам данных, API, браузеру и любым внешним системам. Решает проблему изолированности языковой модели от реального мира.

### 🤖 Agent (Агент)
**Автономная AI-система, способная самостоятельно планировать и выполнять многошаговые задачи.**  
Агент получает цель, разбивает её на шаги, выбирает инструменты, выполняет действия и адаптируется по результатам. Работает в цикле: восприятие → планирование → действие → рефлексия.

### 🔄 Workflow (Рабочий процесс)
**Детерминированная последовательность шагов с AI-компонентами.**  
В отличие от агента, Workflow заранее задаёт, какие шаги нужно выполнить и в каком порядке. AI может участвовать в отдельных шагах, но общий поток контролирует система (код, оркестратор).

## 🔗 Как концепты строятся друг на друге

### Принцип «строительных блоков»:

```
Prompt ──────────────────────────────────────────── ОСНОВА всего
  │
  └─► + правила поведения = Instruction
                │
                └─► + переиспользование = Skill
                              │
                              └─► + внешние данные = MCP
                                            │
                                            └─► + автономность = Agent
                                                        │
                                                        └─► + детерминизм = Workflow
```

### Реальный пример стека для HR-системы:

```yaml
# Уровень 6: Workflow
workflow: "Обработка заявки на найм"
steps:
  - name: "Парсинг резюме"      # Уровень 4: MCP (читает PDF)
  - name: "Оценка кандидата"    # Уровень 5: Agent (анализирует + решает)
    agent:
      instructions: "hr-assistant"  # Уровень 2: Instructions
      skills: ["cv-analysis"]       # Уровень 3: Skills
      prompt: "Оцени кандидата..."  # Уровень 1: Prompt
  - name: "Отправка результата" # Уровень 4: MCP (отправляет email)
```

## 🆚 Ключевые различия в одной строке

| Пара | Ключевое отличие |
|------|-----------------|
| **Prompt vs Instruction** | Разово vs постоянно |
| **Instruction vs Skill** | Правила поведения vs конкретная способность |
| **Skill vs MCP** | Знание (как делать) vs доступ (к чему делать) |
| **MCP vs Agent** | Инструмент vs тот, кто использует инструменты |
| **Agent vs Workflow** | Гибкость/адаптивность vs надёжность/предсказуемость |

## 🎤 Заметки для спикера

- Эта схема — **якорная точка** всей презентации. После неё люди знают, куда идти
- **ASCII-диаграммы** хорошо смотрятся в Markdown — используй их как слайды
- Обрати внимание на строку **«Ключевые различия»** — её можно использовать как quiz
- Хороший момент для **интерактива**: попроси аудиторию угадать, какой уровень использует Siri / Google Assistant / Copilot

## ❓ Возможные вопросы аудитории

**В: Можно ли использовать только один уровень, без остальных?**
> О: Да, каждый уровень работает самостоятельно. Промпт работает без всего остального. Но мощь появляется при комбинировании.

**В: Обязательно ли использовать все 6 уровней в проекте?**
> О: Нет. Простая задача → один промпт. Начни с минимума и добавляй по потребности (принцип KISS — Keep It Simple, Stupid).

**В: Какой уровень самый важный?**
> О: Зависит от задачи. Но если отвечать честно — Instructions, потому что они определяют поведение всей системы и влияют на качество работы каждого другого уровня.
