## 🧩 Кейс 1: Обработка обращений клиентов в банке

### Задача
Банк «ФинансПро» получает 5000 обращений в день через email, чат и форму на сайте. Операторы тратят 3–5 минут на каждое. Нужно автоматизировать обработку, сохранив качество.

---

### Решение через разные подходы

#### Вариант A: Только Prompts (антипаттерн)
```
Оператор вручную копирует обращение → ChatGPT → копирует ответ

Результат:
✗ Каждый оператор пишет свой промпт по-разному
✗ Разное качество ответов
✗ Нет интеграции с CRM
✗ Нет аудиторского следа
✗ 5000 ручных операций в день

Экономия: ~0%
```

#### Вариант B: Instructions + MCPs (базовая автоматизация)
```python
# Instructions: задаём поведение бота поддержки
SYSTEM = """
Ты — ассистент банка ФинансПро.
Помогаешь с: картами, кредитами, платежами, вкладами.
Тон: вежливый, официальный. Язык: русский.
При сложных операционных вопросах: перенаправляй на 8-800-555-01-00.
Никогда не называй остатки счётов без верификации.
"""

# MCP: подключаем CRM и FAQ базу
mcps = [
    CRMMCPServer(connection=crm_db),      # История клиента
    FAQMCPServer(kb_path="./knowledge"),   # База знаний
    TicketMCPServer(jira_url="...")        # Создание тикетов
]

# Результат: AI отвечает с учётом истории клиента и базы знаний
Экономия: ~40% времени операторов (автообработка простых запросов)
```

#### Вариант C: Workflow + Instructions + MCPs (production-ready)
```
WORKFLOW: ticket-processing-pipeline

Step 1: TRIGGER
  Новое обращение из email/chat/form → очередь

Step 2: ENRICHMENT (MCP)
  Получить: история клиента из CRM, тип продуктов, статус

Step 3: CLASSIFICATION (AI + Instructions)
  Категории: billing, technical, complaint, info_request
  Срочность: urgent / normal / low

Step 4: ROUTING (код, детерминированный)
  billing → finance team queue
  complaint → VIP handling
  urgent → skip queue, immediate

Step 5: RESPONSE GENERATION (AI + Skills)
  Применить skill: customer-support-reply
  Использовать: история клиента + FAQ + шаблоны

Step 6: QUALITY CHECK (код)
  Длина ответа: 50-300 слов
  Нет персональных данных в теле письма
  Есть ссылки на конкретные FAQ

Step 7: HUMAN REVIEW (человек, для сложных случаев)
  Если complexity_score > 0.7 → human
  Иначе → автоотправка

Step 8: SEND + LOG (MCP)
  Отправить ответ → обновить CRM → analytics

Результат: 85% обращений обрабатывается автоматически
Экономия: ~70% времени операторов
Аудиторский след: каждый шаг залогирован
```

---

### Вывод по кейсу 1

| Подход | Автоматизация | Качество | Надёжность | Стоимость внедрения |
|--------|--------------|---------|------------|---------------------|
| Только Prompts | 0% | Нестабильное | Нет | Минимальная |
| Instructions + MCP | 40% | Хорошее | Средняя | Средняя |
| **Workflow + все** | **85%** | **Отличное** | **Высокая** | Высокая |

**Вывод:** Для масштабной бизнес-задачи оправдана инвестиция в полный стек.

## 🧩 Кейс 2: Код-ревью в команде разработчиков

### Задача
Стартап из 20 разработчиков хочет улучшить качество кода через AI-ревью каждого PR. Сейчас ревью занимает 30–60 минут и часто откладывается.

---

### Эволюция решения: от промпта до автоматизации

#### Этап 1 (День 1): Промпт-эксперимент
```
Разработчик Иван копирует код в ChatGPT:
"Сделай ревью этого кода"

Результат: Работает! Но каждый пишет свой промпт → разные аспекты проверки
```

#### Этап 2 (Неделя 1): Instructions + Skills в Copilot
```markdown
# .github/copilot-instructions.md

Ты — ревьюер кода в команде стартапа X.

Стандарты кода:
- Python 3.12, FastAPI, Pydantic v2
- Тесты: pytest, минимум 80% coverage
- Безопасность: OWASP Top 10
- Документация: Google-style docstrings

Формат ревью:
- Critical: блокирует merge (баги, безопасность)
- Major: нужно исправить до merge
- Minor: можно в follow-up PR
- Nit: косметика, по желанию
```

```markdown
# SKILL.md — code-review

## Чек-лист ревью (всегда проверяй):
1. Логические ошибки и edge cases
2. SQL Injection, XSS, CSRF
3. Обработка ошибок (except Exception: pass → ❌)
4. Типы данных (type hints везде)
5. Тесты: есть ли на новую функциональность?
6. Performance: N+1 запросы, ненужные joins

## Формат вывода:
```
### 🔴 Critical
- [SECURITY] Строка X: SQL injection через f-string
  Исправление: использовать параметризованные запросы

### 🟡 Major
- [TESTS] Функция Y не покрыта тестами
  
### 🟢 Minor
- [STYLE] Строка Z: слишком длинная (>88 символов)
```
```

**Результат этапа 2:** Все пишут ревью одинаково, Copilot помогает прямо в VS Code.

#### Этап 3 (Месяц 1): Workflow в CI/CD (автоматизация)
```yaml
# .github/workflows/ai-code-review.yml
name: AI Code Review

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  ai-review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      
      - name: Get Changed Files
        id: diff
        run: |
          git diff origin/main...HEAD --name-only > changed_files.txt
          git diff origin/main...HEAD > full_diff.txt
      
      - name: AI Review via API
        run: |
          python scripts/ai_review.py \
            --diff full_diff.txt \
            --skill code-review \
            --instructions .github/copilot-instructions.md \
            --output review_result.json
      
      - name: Post Review Comments
        uses: actions/github-script@v7
        with:
          script: |
            const review = require('./review_result.json');
            await github.rest.pulls.createReview({
              pull_number: context.payload.pull_request.number,
              body: review.summary,
              comments: review.inline_comments,
              event: review.has_critical ? 'REQUEST_CHANGES' : 'COMMENT'
            });
```

**Результат этапа 3:** Каждый PR получает ревью за 2 минуты. Блокировка critical issues автоматически.

---

### Итоговое сравнение по кейсу 2

| Этап | Время ревью | Покрытие | Качество | Усилий |
|------|------------|---------|---------|--------|
| До AI | 45 мин | ~60% PR | Непостоянное | Высокие |
| Этап 1 (Промпт) | 15 мин | 100% | Нестабильное | Средние |
| Этап 2 (Instructions+Skills) | 5 мин | 100% | Хорошее | Низкие |
| **Этап 3 (Workflow)** | **2 мин** | **100%** | **Отличное** | **Минимальные** |

## 🧩 Кейс 3: Эволюция задачи «Анализ вакансий рынка труда»

### Задача
HR-директор хочет знать, что происходит на рынке труда в IT: какие навыки востребованы, как изменились зарплаты, какие компании нанимают активнее всего.

**Ключевой вопрос: как решение эволюционирует от промпта до агента?**

---

### Версия 1.0: Один промпт (День 1)
```
HR-директор: "ChatGPT, что сейчас требуют от Python-разработчиков?"

ChatGPT: "Обычно требуют знание Django, FastAPI, PostgreSQL..."

Проблема: Данные из обучения (устаревшие). Нет актуальной информации.
```

### Версия 2.0: Промпт + MCP для поиска (День 7)
```python
# Добавляем MCP для актуального поиска
mcps = [BraveSearchMCP()]

# Теперь AI ищет актуальные данные
"Найди в интернете последние 10 вакансий Python Developer в Москве
 и проанализируй требования. Акцент на навыки и зарплаты."

Результат: Актуальные данные! Но только 10 вакансий, ручная работа.
```

### Версия 3.0: Agent с MCPs (Месяц 1)
```python
# Агент автономно исследует рынок
research_agent = ReActAgent(
    instructions="""
    Ты — аналитик рынка труда. 
    Собираешь данные о вакансиях, анализируешь тренды.
    Ссылайся на источники. Будь объективен.
    """,
    tools=[
        web_search_mcp,      # Поиск вакансий
        file_write_mcp,      # Сохранение данных
        python_executor_mcp  # Анализ и статистика
    ]
)

task = """
Проанализируй рынок вакансий Python Developer в России за последний месяц:
1. Собери данные с HH.ru, Habr Career, LinkedIn
2. Выдели топ-10 самых востребованных навыков
3. Определи медианную зарплатную вилку
4. Найди топ-5 активно нанимающих компаний
5. Сравни с прошлым кварталом
6. Дай прогноз на следующий квартал
Сохрани отчёт в /reports/labor_market_q4_2024.md
"""

result = research_agent.run(task)
# Агент сам решает: какие сайты искать, как парсить, как анализировать
# Занимает 15-20 минут, делает 30-50 LLM-вызовов
```

### Версия 4.0: Workflow (автоматический еженедельный отчёт)
```python
# Workflow для регулярного запуска (каждый понедельник, 8:00)

    ]
```

## 🔑 Ключевые уроки из кейсов

### Урок 1: Начинай с малого
> Ни один из успешных кейсов не начался с Workflow. Всегда начинай с промпта, проверяй ценность, потом добавляй сложность.

### Урок 2: Правильный инструмент для масштаба
> Промпты хороши для единичных случаев. Workflow — для тысяч. Агенты — для нестандартных ситуаций внутри Workflow.

### Урок 3: Не бойся комбинировать
> Лучшие решения используют несколько уровней: Instructions задают поведение, MCPs дают данные, Skills стандартизируют логику, Workflow обеспечивает надёжность.

### Урок 4: Мониторинг обязателен
> В каждом кейсе Production-решение включало логирование и мониторинг. AI без мониторинга — чёрный ящик.

### Урок 5: Human-in-loop там, где риск высок
> Банковский кейс: сложные случаи → человек. DevOps кейс: деструктивные действия → человек. Это не слабость — это правильная архитектура.

## 🎤 Заметки для спикера

- **Кейс банка** — хорошо знаком корпоративной аудитории. Обработка обращений = боль многих компаний
- **Кейс code-review** — прямо актуален для IT-аудитории. Многие используют Copilot
- **Кейс эволюции** — показывает «путь героя»: от наивного промпта к правильной архитектуре. Аудитория видит прогрессию
- Можно предложить аудитории **свой кейс** из практики
- Подчеркни: **ни один кейс не использует все 6 уровней без причины** — только то, что нужно
- Время на этот слайд: **10 минут**
