# 💬 Prompts — Разовые запросы к AI

---

## 1. Заголовок и краткое определение

**Prompt (промпт)** — это текстовый запрос, который пользователь передаёт языковой модели для получения ответа. Это самый базовый и фундаментальный способ взаимодействия с AI: написал → получил ответ → взаимодействие завершено.

---

## 2. Подробное объяснение

### Простыми словами
Промпт — это буквально то, что ты пишешь в ChatGPT, Claude или Copilot. «Переведи этот текст», «Напиши функцию», «Объясни, что такое Docker» — всё это промпты. Каждый промпт — самостоятельный, независимый запрос.

### Технически
С точки зрения работы LLM:
- Промпт — это входная последовательность токенов
- Модель обрабатывает весь контекст (включая системный промпт, если есть) и генерирует ответ
- После ответа модель «не помнит» разговор — каждый вызов API независим
- В диалоговых интерфейсах (ChatGPT) история подставляется автоматически, но технически это просто более длинный промпт

```
┌─────────────────────────────────────────────┐
│               CONTEXT WINDOW                │
│                                             │
│  [System Prompt]  [User Message]            │
│                        │                   │
│                        ▼                   │
│                  [LLM Processing]           │
│                        │                   │
│                        ▼                   │
│                  [Generated Output]         │
└─────────────────────────────────────────────┘
```

### Составляющие хорошего промпта
```
Хороший промпт = Роль + Контекст + Задача + Формат + Ограничения

Пример:
"Ты — опытный Python-разработчик. (роль)
 У меня есть список из 10 000 пользователей в памяти. (контекст)
 Напиши функцию для поиска дубликатов по email. (задача)
 Верни как Python-код с docstring. (формат)
 Используй только стандартную библиотеку. (ограничения)"
```

---

## 3. Аналогия из реальной жизни

**Промпт = Разовый заказ в кафе**

Ты подходишь к стойке и говоришь: «Дайте мне капучино, средний, без сахара». Бариста делает твой заказ. Ты уходишь. На следующий день приходишь снова — бариста не помнит тебя и твои предпочтения. Ты снова объясняешь заказ с нуля.

- Каждый визит = новый промпт
- Нет «постоянного клиента» = нет памяти между сессиями  
- Результат зависит от того, насколько чётко ты объяснил
- Если хочешь всегда получать одно и то же — нужна «карточка постоянного клиента» (= Instructions)

## 4. Как это работает — Механика и техники

### Базовый цикл:
```
Пользователь пишет текст
        │
        ▼
Текст токенизируется
        │
        ▼
Модель обрабатывает токены в контексте
        │
        ▼
Модель генерирует ответ (авторегрессивно)
        │
        ▼
Ответ декодируется в текст
        │
        ▼
Пользователь получает результат
```

### Техники промптинга:

#### Zero-Shot (без примеров)
```
"Переведи на английский: Сегодня хорошая погода"
```
Просто задача без примеров. Работает для простых запросов.

#### Few-Shot (с примерами)
```
"Классифицируй тональность:

Текст: 'Отличный сервис!' → Положительный
Текст: 'Ужасное качество' → Отрицательный
Текст: 'Обычный продукт'  → Нейтральный

Текст: 'Очень доволен покупкой' → ?"
```
Примеры помогают модели понять формат и контекст задачи.

#### Chain-of-Thought (цепочка рассуждений)
```
"Реши задачу и покажи ход рассуждений шаг за шагом:

Если поезд едет 120 км/ч и преодолевает расстояние 360 км,
сколько времени займёт поездка?

Думай пошагово:"
```
Принуждает модель «думать вслух», что значительно повышает точность сложных задач.

#### Role Prompting (ролевой промпт)
```
"Ты — эксперт по кибербезопасности с 15 годами опыта.
 Проанализируй этот код на уязвимости:
 [код]"
```

#### Structured Output (структурированный вывод)
```
"Проанализируй продукт и верни результат в JSON:
{
  'strengths': [],
  'weaknesses': [],
  'opportunities': [],
  'threats': []
}"
```

## 5. Примеры кода и использования

### Пример 1: Прямой вызов через API
```python
import anthropic

client = anthropic.Anthropic(api_key="your-key")

message = client.messages.create(
    model="claude-opus-4-5",
    max_tokens=1024,
    messages=[
        {
            "role": "user",
            "content": "Напиши функцию на Python для валидации email-адреса"
        }
    ]
)

print(message.content[0].text)
```

### Пример 2: Промпт с шаблоном (Python f-string)
```python
def analyze_code(code: str, language: str) -> str:
    prompt = f"""
    Проанализируй следующий {language}-код:
    
    ```{language}
    {code}
    ```
    
    Найди:
    1. Потенциальные баги
    2. Проблемы производительности  
    3. Нарушения best practices
    
    Для каждой проблемы укажи строку и способ исправления.
    """
    return call_llm(prompt)
```

### Пример 3: Хороший vs Плохой промпт
```
❌ ПЛОХОЙ ПРОМПТ:
"напиши что-нибудь про питон"

Проблемы:
- Нет конкретики (язык или животное?)
- Нет формата ответа
- Нет контекста цели

✅ ХОРОШИЙ ПРОМПТ:
"Напиши краткое введение (200 слов) для начинающих разработчиков 
 о языке программирования Python. 
 Включи: историю создания, ключевые преимущества, типичные сферы применения.
 Стиль: дружелюбный, без жаргона."

Улучшения:
✓ Конкретная тема
✓ Указана аудитория
✓ Ограничение по длине
✓ Список требований к содержанию
✓ Задан стиль
```

### Пример 4: Промпт для генерации тестов (Copilot-стиль)
```
# Напиши unit-тесты для следующей функции.
# Используй pytest. Покрой edge cases: пустой список, один элемент,
# отрицательные числа, очень большие числа.

def calculate_average(numbers: list[float]) -> float:
    if not numbers:
        raise ValueError("Empty list")
    return sum(numbers) / len(numbers)
```

## 6. Плюсы

1. **Мгновенный старт** — не нужна никакая настройка. Открыл ChatGPT, написал — получил результат. Входной барьер равен нулю.

2. **Максимальная гибкость** — каждый запрос уникален. Можно попросить AI выступить в совершенно новой роли, решить нестандартную задачу, поменять формат ответа.

3. **Итеративность** — легко уточнять и улучшать: «Сделай то же самое, но короче», «Добавь примеры», «Переделай в стиле Python 3.12».

4. **Не требует кода или инфраструктуры** — бизнес-пользователи, аналитики, менеджеры могут использовать AI без технических знаний.

5. **Быстрое прототипирование** — можно быстро проверить идею до того, как инвестировать в автоматизацию (Instructions, Workflows).

6. **Универсальность** — один формат для тысяч задач: перевод, анализ, генерация, резюмирование, отладка.

---

## 7. Минусы / Ограничения

1. **Нет памяти между сессиями** — если закрыл вкладку, AI «забыл» весь контекст. Завтра нужно объяснять снова.

2. **Непоследовательность** — один и тот же промпт может давать разные ответы. Нет гарантии стабильного поведения. Критично для производственных систем.

3. **Нет доступа к реальным данным** — AI не знает, что происходит в вашей базе данных, файлах, CRM прямо сейчас. Знания ограничены датой обучения модели.

4. **Ограничение контекстного окна** — нельзя передать «бесконечно» много информации в одном промпте. У GPT-4 это ~128K токенов, у Claude ~200K.

5. **Повторяемость** — сложные промпты приходится копировать и вставлять снова и снова. Нет механизма сохранения «лучших практик» кроме copy-paste.

6. **Prompt Injection риск** — если промпт принимает пользовательский ввод, злоумышленник может изменить поведение системы через специально сконструированный текст.

## 8. Когда использовать / Когда НЕ использовать

### ✅ Используй промпты когда:
- Разовая задача: перевод документа, анализ текста, генерация кода
- Прототипирование и исследование возможностей AI
- Нетехническая аудитория без доступа к системным настройкам
- Задача уникальна и не повторяется
- Нужен быстрый ответ без настройки
- Интерактивная работа: брейнсторминг, Q&A сессии

### ❌ НЕ используй промпты когда:
- Нужно единообразное поведение AI в продакшене (используй Instructions)
- Задача повторяется регулярно с одними и теми же правилами (используй Skills)
- Нужен доступ к актуальным внешним данным (используй MCPs)
- Задача многошаговая и требует принятия решений (используй Agents)
- Нужна надёжная бизнес-логика с гарантированными шагами (используй Workflows)

## 9. Сравнение с соседними концептами

### Prompts vs Instructions

| Критерий | Prompts | Instructions |
|----------|---------|-------------|
| Длительность | Разовые | Постоянные |
| Кто задаёт | Конечный пользователь | Разработчик/администратор |
| Место в запросе | User message | System message |
| Влияние | Один ответ | Вся сессия/проект |
| Изменяемость | Каждый раз | Редко меняются |

**Пример различия:**
```
📋 INSTRUCTION (задаётся один раз):
"Ты — HR-бот компании ABC. Отвечай на вопросы о вакансиях.
 Всегда будь вежлив. Не обсуждай конкурентов."

💬 PROMPT (каждый раз новый):
"Какие вакансии открыты в отделе разработки?"
"Каков процесс собеседования?"
"Какая зарплата?"
```

### Prompts vs Skills

| Критерий | Prompts | Skills |
|----------|---------|--------|
| Переиспользование | Нет (copy-paste) | Да (вызов по имени) |
| Упаковка | Текст в чате | Файл с инструкциями |
| Вызов | Явно пишешь | По имени или автоматически |
| Сложность | Простая | Может быть сложной |

## 10. Заметки для спикера

- **Начни с личного примера**: «Вот что я написал в ChatGPT вчера...» — аудитория сразу узнаёт себя
- **Zero-shot/Few-shot/CoT** — это техники, которые реально работают. Покажи «до/после» — эффект впечатляет
- **Плохой промпт** смешной и знакомый — аудитория смеётся, потому что сама так делала
- Подчеркни: **промпты — это фундамент**. Даже агент внутри использует промпты. Не нужно их «перерастать»
- **Prompt Injection** — хорошая точка для упоминания безопасности. Аудитория IT-специалистов оценит
- Время на этот слайд: **5–7 минут**

## 11. Возможные вопросы аудитории

**В: Есть ли разница между "промптом" и "вопросом к AI"?**
> О: Технически — нет, это синонимы в обиходном использовании. Но в профессиональном контексте «промпт» — это продуманный запрос, который включает контекст, формат и ограничения. «Вопрос» — это просто вопрос. Хороший промпт = грамотно сформулированный вопрос.

**В: Как написать промпт, чтобы AI всегда отвечал одинаково?**
> О: Это невозможно гарантировать только промптом из-за стохастичности генерации. Но можно снизить вариативность: (1) добавить `temperature: 0` в настройках API, (2) задать чёткий формат ответа, (3) использовать Instructions для постоянных правил.

**В: Можно ли автоматизировать отправку промптов?**
> О: Да! Это и есть переход к следующим уровням. Автоматическая отправка заготовленных промптов → это Skills. С логикой и принятием решений → это Agents. С заданной последовательностью → это Workflows.

**В: Что такое "prompt engineering" — это профессия?**
> О: Это скорее навык, чем профессия. Умение составлять эффективные промпты — ценный навык для любого специалиста, работающего с AI. Отдельная роль «prompt engineer» уже теряет актуальность, так как современные модели лучше понимают естественный язык и требуют меньшей «инженерии».

**В: Как защититься от prompt injection?**
> О: Несколько подходов: (1) не включать пользовательский ввод в system prompt, (2) валидировать пользовательский ввод перед подстановкой, (3) использовать специальные разделители для отделения инструкций от данных, (4) работать с минимальными привилегиями (не давать AI доступ к тому, что не нужно).
