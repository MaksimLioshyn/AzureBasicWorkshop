# 🔌 MCPs — Model Context Protocol

---

## 1. Заголовок и краткое определение

**MCP (Model Context Protocol)** — это открытый стандарт, разработанный Anthropic в 2024 году, который позволяет языковым моделям подключаться к внешним инструментам, данным и системам через унифицированный протокол. MCP решает проблему «закрытости» AI: делает языковую модель частью реального цифрового мира.

---

## 2. Подробное объяснение

### Простыми словами
До MCP у каждой AI-системы были свои способы подключения к инструментам: ChatGPT плагины работали только в ChatGPT, Copilot расширения — только в Copilot. Это создавало хаос: один и тот же файловый менеджер нужно было реализовывать по-разному для каждого AI.

MCP — это как **стандартный разъём USB**: один протокол для всего. Разработал инструмент по стандарту MCP — и он работает с любым совместимым AI.

### Технически
MCP — это **клиент-серверная архитектура**:
- **MCP-сервер** — предоставляет инструменты и данные (файловая система, БД, GitHub API, Slack)
- **MCP-клиент** — это AI-хост (Copilot, Claude Desktop, любой совместимый агент)
- **Транспорт** — взаимодействие через stdio, HTTP, WebSocket

```
┌─────────────────────────────────────────────────────────────┐
│                      MCP АРХИТЕКТУРА                         │
│                                                             │
│   ┌──────────────────────────────────────────────────────┐  │
│   │               LLM HOST (MCP Client)                  │  │
│   │    Claude Desktop / VS Code Copilot / Custom Agent   │  │
│   └───────────────────────┬──────────────────────────────┘  │
│                           │  MCP Protocol                   │
│           ┌───────────────┼───────────────┐                 │
│           ▼               ▼               ▼                 │
│   ┌───────────┐   ┌───────────┐   ┌───────────┐            │
│   │ MCP Server│   │ MCP Server│   │ MCP Server│            │
│   │ File Sys  │   │  GitHub   │   │  Database │            │
│   └───────────┘   └───────────┘   └───────────┘            │
│        │                │                │                  │
│   [Ваши файлы]    [Репозитории]     [PostgreSQL]           │
└─────────────────────────────────────────────────────────────┘
```

### Что MCP-сервер предоставляет AI:
```
Resources  — данные для чтения (файлы, БД записи, страницы)
Tools      — функции для вызова (создать файл, отправить запрос)
Prompts    — готовые шаблоны запросов
```

## 3. Аналогия из реальной жизни

**MCP = USB-разъём для AI**

До изобретения USB каждое устройство (принтер, клавиатура, мышь) имело свой разъём. Подключить новое устройство = купить специальный кабель.

USB стандартизировал интерфейс: один разъём для всего. Появился USB-принтер — работает с любым компьютером.

Аналогично:
- **До MCP**: каждый AI имел свои плагины/инструменты → несовместимость, дублирование работы
- **После MCP**: написал MCP-сервер для своей базы данных → работает с Claude, Copilot, и любым другим MCP-совместимым AI

**Дополнительная аналогия:**
MCP = **Стандарт REST API для AI**  
Как REST позволил веб-приложениям разговаривать между собой, MCP позволяет AI-системам взаимодействовать с любыми данными и инструментами.

## 4. Как это работает — Механика

### Схема взаимодействия:

```
1. ПОЛЬЗОВАТЕЛЬ ЗАДАЁТ ЗАДАЧУ
   "Найди все файлы с ошибками в логах за сегодня"
   
2. AI АНАЛИЗИРУЕТ ЗАДАЧУ
   Понимает, что нужен доступ к файловой системе
   
3. AI ВЫЗЫВАЕТ MCP TOOL
   {
     "tool": "read_file",
     "arguments": {
       "path": "/var/log/app/*.log",
       "filter": "ERROR",
       "date": "today"
     }
   }
   
4. MCP СЕРВЕР ВЫПОЛНЯЕТ ДЕЙСТВИЕ
   Читает файлы, фильтрует ошибки
   
5. MCP СЕРВЕР ВОЗВРАЩАЕТ ДАННЫЕ
   {"errors": [...], "count": 47}
   
6. AI ОБРАБАТЫВАЕТ ДАННЫЕ И ОТВЕЧАЕТ
   "Нашёл 47 ошибок. Основные проблемы: ..."
```

### Протокол запроса (JSON-RPC 2.0):
```json
// AI → MCP Server: вызов инструмента
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "read_file",
    "arguments": {
      "path": "/data/sales.csv"
    }
  }
}

// MCP Server → AI: результат
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "date,product,amount\n2024-01-01,Widget,100\n..."
      }
    ]
  }
}
```

## 5. Примеры кода и использования

### Пример 1: Настройка MCP в Claude Desktop (конфиг)
```json
// ~/.claude/claude_desktop_config.json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/projects"],
      "description": "Доступ к файловой системе проектов"
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}"
      }
    },
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "POSTGRES_CONNECTION_STRING": "postgresql://user:pass@localhost/mydb"
      }
    }
  }
}
```

После настройки AI может говорить: «Прочитай файл config.py» или «Покажи последние 10 PR в репозитории».

### Пример 2: Создание кастомного MCP-сервера (Python)
```python
# custom_mcp_server.py
from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent
import json

# Создаём MCP сервер
server = Server("company-crm-server")

@server.list_tools()
async def list_tools():
    """Объявляем доступные инструменты"""
    return [
        Tool(
            name="get_customer",
            description="Получает данные клиента из CRM по ID или email",
            inputSchema={
                "type": "object",
                "properties": {
                    "identifier": {
                        "type": "string",
                        "description": "ID или email клиента"
                    }
                },
                "required": ["identifier"]
            }
        ),
        Tool(
            name="get_deals",
            description="Возвращает список сделок клиента",
            inputSchema={
                "type": "object", 
                "properties": {
                    "customer_id": {"type": "string"},
                    "status": {
                        "type": "string",
                        "enum": ["open", "closed", "all"]
                    }
                },
                "required": ["customer_id"]
            }
        )
    ]

@server.call_tool()
async def call_tool(name: str, arguments: dict):
    """Обрабатываем вызовы инструментов"""
    if name == "get_customer":
        customer = crm.get_customer(arguments["identifier"])
        return [TextContent(type="text", text=json.dumps(customer))]
    
    elif name == "get_deals":
        deals = crm.get_deals(
            customer_id=arguments["customer_id"],
            status=arguments.get("status", "all")
        )
        return [TextContent(type="text", text=json.dumps(deals))]

# Запускаем сервер
async def main():
    async with stdio_server() as streams:
        await server.run(*streams)
```

### Пример 3: MCP-сервер для Azure-ресурсов (реальный кейс)

```
"Создай storage account в East US"

"Проверь статус всех App Services"
→ AI вызывает azure-mcp → проверяет статусы → выводит отчёт
```

## 6. Плюсы

1. **Стандартизация** — один протокол для всех AI и всех инструментов. Разработал один раз — работает везде.

2. **Реальные данные в реальном времени** — AI получает актуальную информацию из вашей системы, а не знания из обучающих данных 2023 года.

3. **Безопасность** — MCP-сервер контролирует, к чему именно AI получает доступ. Можно дать доступ только к нужным данным с нужными правами.

4. **Экосистема** — огромная библиотека готовых MCP-серверов. Не нужно писать с нуля интеграцию с GitHub, Slack, Jira.

5. **Изоляция** — MCP-сервер — отдельный процесс. Проблема в сервере не ломает AI-хост и наоборот.

6. **Расширяемость** — любая система может стать источником данных для AI, написав свой MCP-сервер.

## 7. Минусы / Ограничения

1. **Молодой стандарт** — MCP появился в ноябре 2024. Экосистема ещё формируется, возможны breaking changes.

2. **Накладные расходы на инфраструктуру** — нужно запускать и поддерживать MCP-серверы. Для простых задач это избыточно.

3. **Безопасность инструментов** — если AI получает права на запись (create_file, delete_record) — нужен тщательный аудит и ограничение привилегий. Принцип least privilege обязателен.

4. **Задержки** — каждый вызов MCP = сетевой или процессный вызов. Для быстрых задач это критично.

5. **Не для бизнес-логики** — MCP предоставляет доступ к данным, но не содержит логики обработки. Это задача для Skills и Agents.

## 8. Когда использовать / Когда НЕ использовать

### ✅ Используй MCPs когда:
- AI нужны актуальные данные из внешних систем (БД, API, файлы)
- Хочешь дать AI возможность выполнять действия (отправить email, создать запись)
- Строишь AI-агента, которому нужны инструменты
- Нужна стандартная интеграция с популярными сервисами (GitHub, Slack, Jira)
- Разрабатываешь собственный AI-инструмент для командного использования

### ❌ НЕ используй MCPs когда:
- AI нужны только базовые способности (генерация текста, перевод) — это работает без MCP
- Задача разовая и не требует автоматизации
- Данные уже есть в промпте — не нужен лишний слой
- Команда не имеет ресурсов на поддержку MCP-инфраструктуры

## 9. Сравнение с соседними концептами

### MCPs vs Skills

| Критерий | MCPs | Skills |
|----------|------|--------|
| Что предоставляют | Данные и инструменты | Способности и алгоритмы |
| Где живут | Внешний сервер/процесс | Текстовый файл с инструкциями |
| Что содержат | Подключения к системам | Инструкции для AI |
| Аналогия | Рабочий инструмент/станок | Профессиональный навык |
| Пример | Читать файл с диска | Анализировать содержимое файла |

### MCPs vs Agents

| Критерий | MCPs | Agents |
|----------|------|--------|
| Роль | Поставщик инструментов | Потребитель инструментов |
| Решения | Не принимает | Принимает самостоятельно |
| Автономность | Нет | Да |
| Управление | Пассивный | Активный |

## 10. Заметки для спикера

- **Аналогия USB** — работает безотказно. Любой IT-специалист сразу понимает ценность стандартизации
- **Покажи конфиг** Claude Desktop или VS Code с MCP — это «вау-момент»: «вот как AI получает доступ к вашим данным»
- **Безопасность** — важная тема для корпоративной аудитории. Подчеркни, что MCP-сервер контролирует права доступа
- **Azure MCP** — если аудитория работает с Azure, живая демонстрация `@azure/mcp` очень впечатляет
- **Свежесть стандарта** (ноябрь 2024) — говорит о том, что тема очень актуальная
- Время на этот слайд: **7–8 минут**

## 11. Возможные вопросы аудитории

**В: Чем MCP отличается от function calling в OpenAI?**
> О: Function calling — проприетарный механизм OpenAI только для их моделей. MCP — открытый стандарт, работающий с любым совместимым AI. Концептуально похожи, но MCP более стандартизирован и переносим между провайдерами.

**В: Может ли AI через MCP удалить важные данные?**
> О: Только если MCP-сервер предоставляет такую возможность и AI решит её использовать. Это риск, который нужно контролировать: (1) не давать MCP-серверу destructive операции без необходимости, (2) добавлять подтверждение человека перед деструктивными действиями, (3) использовать read-only режим там, где достаточно чтения.

**В: Работает ли MCP с GPT-4 и Gemini?**
> О: MCP — открытый стандарт, и поддержку добавляют разные игроки. На момент создания материала полная нативная поддержка — у Anthropic Claude и Microsoft Copilot. OpenAI и Google движутся в ту же сторону (OpenAI анонсировал поддержку MCP в 2025).

**В: Как MCP решает проблему безопасности передачи данных?**
> О: MCP использует локальный transport (stdio) или зашифрованный HTTP. Данные проходят через MCP-сервер, который сам контролирует аутентификацию, авторизацию и то, что отдаёт AI. При правильной настройке AI видит только то, что ему разрешено.
